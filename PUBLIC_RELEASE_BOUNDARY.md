# HFWM Public Release Boundary

This repository is the public scientific and publication home of the **Human Function World Model (HFWM)**. It is designed to make HFWM citable, auditable, criticizable, reproducible where appropriate, and extensible without publishing the complete commercial production implementation.

## Public by design

Public material may include:

- HFWM definitions and scientific scope;
- UOHF dependency and semantic boundaries;
- the public 18-core/104-specific capacity coordinate;
- high-level internal/external task semantics;
- formal state, evidence, action, feedback and longitudinal-update architecture;
- public role and governance boundaries of Functional Bridge;
- references to HRA, WPP, VHT and other scientific resources where applicable;
- non-sensitive competency cases and examples;
- public evaluation methods and benchmark definitions;
- scientific papers, citation metadata and version history.

## Not released merely by this repository

The following remain outside the public release unless separately authorized:

- complete production Demand→Capacity requirement matrices;
- complete production relation topology;
- private Functional Bridge source maps, claim registries, coverage ledgers or review queues;
- private person-specific reasoning rules;
- production decision weights, thresholds and policy matrices;
- private assessment and intervention mappings;
- prompts, provider-context assembly, provider fallback or model-routing rules;
- production retrieval/reranking implementation and private indexing parameters;
- production database schemas, private APIs, payload contracts or security rules;
- private datasets, member data or operational records;
- billing, entitlement, pricing or commercial product logic;
- unpublished commercial implementation know-how.

## Knowledge is not evidence

General scientific knowledge, including a Functional Bridge proposition, is not automatically a fact about an individual person.

Person-specific judgment requires admissible person-specific evidence, provenance, authority, safety and the applicable governance rules.

## Public paper ≠ open-source product

A public HFWM paper can define a scientific architecture without disclosing the proprietary implementation used by a commercial system.
