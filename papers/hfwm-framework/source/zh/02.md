# 4. 人体功能世界模型的正式定义与核心承诺

| 定义：人体功能世界模型，是以同一个完整的人为持续建模对象，以人体功能为统一组织坐标，持续表示和推理该人在内部与外部需求下的状态，表示可能的状态转移，选择受治理行动，并随时间更新个体模型。UOHF 的本体根语义仍以内部/外部 Demand 为要求对象；在当前运行层中，受治理的 INTERNAL_TASK / EXTERNAL_TASK 位于 Demand 之前，负责形成或追溯需求。模型连接人体结构与生理过程、疾病与损伤、功能能力、Actual Engagement Process（实际调用过程）及其功能调用断言、表现、代价、边界、恢复、证据、医学信息、专业与生活条件、行动及其随时间发生的变化。经过校准的未来状态预测属于分阶段验证的实证能力，不是假定所有实现已经具备的属性。 |
|---|

这个定义包含四个承诺。第一，持续对象是完整的人，而不是器官、疾病、测试结果、某个专业或某个动作。第二，人体功能是组织中心，不是建模边界。第三，在当前运行层中，受治理的内部任务/外部任务表示是 Demand 之前的统一运行入口；UOHF 已发表的根语义仍然以内部/外部 Demand 为要求对象。第四，真实状态、证据、推理、行动、反馈和模型更新必须分层，不能把信息表示与人体本身混为一谈。

HFWM 并不把“人的一切”都还原成人体功能。人的社会身份、价值观、偏好、家庭关系等并不因此被重新定义为人体功能。人体功能提供的是一个统一的运行视角：身体如何维持生命、应对疾病和损伤、恢复、行动，并在现实世界中完成生活。

UOHF 的根定义保持不变：人体功能是身体为满足内部和外部需求而能够被适当调用的能力[1-3]。HFWM 在此基础上增加完整人状态、历史、动态变化、协作、行动和纵向更新。

兼容性说明：UOHF Definition 2.1 把 Demand 定义为上位要求对象，并主要把 Task 作为外部需求的操作化入口。后续 UOHF Runtime 治理为了统一执行顺序，引入受治理的 INTERNAL_TASK / EXTERNAL_TASK 两类 Task，在 Runtime 中先确认 Task，再形成或追溯 Demand。HFWM 采用这一运行约定，但它只属于执行层：不重新定义 Demand，不把疾病、症状、评估、服务工作流或动作模板变成 Task，也不反向改写已经发表的 UOHF 2.1 根语义。

# 5. 完整的人作为持续建模主体

设 p 表示一个具体的人。HFWM 要求所有个体级事实在不同时间、专业和数据源中都持续绑定到同一个 p。化验结果、影像、动作观察、饮食史、睡眠报告、工作受限、手术记录、家庭支持条件和运动反应可以同时存在，但它们只是关于同一个人的不同类型事实，不是对这个人相互竞争的定义。

完整人的潜在或建模状态 X_t 可以包含多尺度生理、结构、认知、行为、医学、环境和恢复维度[3]。系统能够观察到的永远只是一部分，因此必须区分“这个人真实存在的状态”和“当前证据支持的模型表示”。

| 建模组成 | 示例 | 在 HFWM 中的作用 |
|---|---|---|
| 身体状态 | 结构、循环、呼吸、代谢、免疫与修复过程 | 实现基础、限制条件、内源状态变化 |
| 医学状态 | 疾病、损伤、手术、药物、限制、安全 | 背景、风险、内部任务触发和行动边界 |
| 人体功能层 | 能力估计、功能调用断言/推断、代价、边界、储备、恢复状态 | 核心运行表示；实际调用过程仍是独立的真实发生过程 |
| 认知与行为状态 | 注意、认知、情绪、行为、自我管理 | 能力、条件与行动因素 |
| 环境与支持 | 家庭、工作、辅助器具、家庭成员、照护者、社区 | 需求/条件改变与外部支持 |
| 历史 | 既往疾病、暴露、干预、恢复和历史状态版本 | 纵向记忆与比较 |

*表 1｜完整人状态的示意组成。该表可扩展，并不意味着每个病例都能观察到全部变量。*

# 6. 内部任务与外部任务

## 6.1 外部任务

外部任务包括自我照护、进食、移动、沟通、学习、工作、家庭责任、社会参与、运动、竞技以及对环境变化的应对。同一个任务在不同速度、负荷、时长、精度、环境、辅助条件和生命周期阶段下会产生不同需求。

## 6.2 内部任务

内部任务是对身体内部目标或挑战的受治理运行表示；只有在合法激活以后，它才产生或具体化相应的内部 Demand。真正“必须被满足的要求”是 Demand，而不是 Task 本身。内部任务身份可以覆盖生命维持、内环境调节、防御、止血、损伤控制、组织修复、稳态恢复、恢复、适应、睡眠—觉醒调节、生长发育和生殖等内部目标。疾病和损伤不是内部任务本身，只能作为 trigger/context 触发受治理的内部任务候选；正式运行不得仅凭病名或症状关键词硬生成内部任务。

这一区分使“自愈”和“恢复”真正进入世界模型。感染可以触发防御、免疫调节、体温调节、循环与能量分配、组织保护和恢复任务；创伤可以触发止血、损伤控制、保护、修复、重塑和可用能力恢复；手术以后既有内部恢复任务，也可能同时出现移动、自我照护、交流、进食、工作和运动方面的外部任务限制。

## 6.3 内外任务耦合

内部任务和外部任务并不互相隔离。运动是外部任务，但会产生循环、呼吸、热调节、能量供给和恢复等内部需求；感染首先是内部挑战，但会降低工作、行走、沟通或社会参与能力。因此当同一个人的状态同时受到多项需求影响时，HFWM 需要表示任务集合，而不是只保留一个孤立任务。

```text
任务（内部 / 外部）
→ 需求
→ 所需人体功能能力
→ 当前能力
→ 实际调用过程
→ 观察反应 / 表现 / 代价 / 边界 / 恢复
→ 证据 / 断言 / 推断 / 判断
→ 行动 / 复评
```

# 7. 功能能力、实际调用过程与调用模式推断

人体功能能力回答：这个人的身体在当前条件下能够提供什么本事。按照既有形式框架，Actual Engagement Process（实际调用过程）是特定人、需求、情境与时间下，所需人体功能真实发生的运行过程；Functional Engagement Assertion（功能调用断言）则是带证据、来源与规则版本的表示对象，用来记录某项所需人体功能是否有证据支持其实际运行[3]。本文在上下文类型已经明确时才把二者简称为“实际调用”。能力与调用必须分开，因为任务失败不能直接证明能力不足，任务完成也不能证明调用一定适当或代价可控；一个能力可以存在，但在当前需求下并没有被有效组织起来[1-3]。

最基本的运行判断由两个主轴组成：当前能力是否覆盖需求，以及关于实际调用的证据支持到什么程度。能力可以相对 Demand 充分或不足；另外，Engagement-Pattern Inference（调用模式推断）可以根据证据被分类为适当、代偿、受限、未建立、无法确定或其他受治理值[3]。这些属于认识层分类，不能被写成实际调用过程本身。能力问题与调用问题可以并存；证据不足不是第三种人体生物学问题，而是认识状态。

这一区分形成从生物状态到现实生活之间的功能桥梁。生理或生物力学模型可以约束能力估计；真实任务观察和重复反应可以帮助判断实际调用。任何一个单独维度都不能直接等同于完整人状态。

## 7.1 UOHF 人体功能能力坐标系

HFWM 在把能力绑定到具体需求之前，需要一套受治理的坐标来说明“完整的人具有哪些稳定人体功能能力”。当前公开的 UOHF 人体功能能力体系 V1.0 提供 18 项 CORE_CAPACITY（核心人体功能能力）以及其下 104 项具体能力；在形式本体中，具体能力根据语义分别属于 SUBCAPACITY 或 CAPACITY_COMPONENT[12]。这些对象都以完整的人为主语，不能与解剖结构、生理过程、任务、一次表现、测量结果或状态标签混为一谈。18+104 是当前版本在明确纳入/排除规则下形成的可审计结果，而不是永远不能增加新能力的封闭数量。

在 HFWM 中，这套能力体系是“坐标系”，不是固定检查清单。受治理的 INTERNAL_TASK 或 EXTERNAL_TASK 使 Demand 明确；Demand 决定当前真正需要哪些能力；随后再根据个体证据形成 Current Capacity，并判断这些已有能力在现实任务中的 Actual Engagement Process。因此，18+104 回答“有哪些稳定能力可以被规范引用”，HFWM 则进一步回答“现在需要哪些、这个人当前有多少、实际怎样发挥，以及这些事实怎样随时间变化”。

# 8. 结构、生理、疾病、损伤与恢复都在 HFWM 内部

HFWM 不把解剖、生理、疾病或恢复放到模型外面。结构提供实现与承载基础；生理过程实现、调节并改变能力；疾病和损伤改变内部条件与安全边界；恢复过程改变未来的可用能力和功能边界。HFWM 需要防止的是类型混淆：结构不是能力，某个生理过程不自动等于完整人的人体功能，疾病不是任务，表现不是原因，测量结果也不是完整状态。

因此一个完整人的状态转移可以同时包含“生理状态变化”和“人体功能状态变化”。一次干预可以改变炎症、灌注、睡眠或组织修复，也可以改变这个人能否站立、吃饭、交流、工作、训练或恢复。模型应保留不同尺度，并显式建立它们之间的关系。

自愈不应被编码成一个不透明的单一结果，也不应被压缩成一个没有内部结构的单一任务。在存在相应规范内部任务身份与受治理触发规则时，HFWM 可以把自愈与恢复表示为防御、止血、调节、修复、稳态恢复、恢复与适应等多个内部任务，以及各任务产生的 Demand、所需人体功能能力和这些能力真实发生的 Actual Engagement Process（实际调用过程）。这并不要求把每一个生理过程机械改写成 Task。纵向观察反应与状态变化共同表明自愈和恢复是在推进、部分完成还是失败。这样既让生理变化获得人体功能意义，又不把生理学还原成人体功能。

## 8.1 Functional Bridge：受治理的知识关系层

完整人的世界模型还需要一层解释性知识，把稳定的人体功能能力继续连接到实现或限制这些能力的解剖结构、空间组织、生理与生物过程、跨能力组织、反应模式、状态/时间/变化以及证据边界。在当前 HFWM 架构中，这一角色由 Functional Bridge 承担。

Functional Bridge 不是新的本体层，不是 UOHF 的 A14，也不改变 18 项核心能力和 104 项具体能力的身份、层级或定义。它也不是某个具体人的个体证据。Bridge 命题可以支持科学解释与知识检索，但不能仅凭自身形成个体疾病诊断、因果归因、能力问题、调用问题或行动处方。若某个命题未来考虑进入正式 UOHF，必须另走本体治理；若用于个体判断，还必须有独立合格的个体证据和专业权限。

## 8.2 HRA 与 WPP：结构和生理科学参考来源

Functional Bridge 可以把外部参考资源作为解释命题的来源与溯源依据，但不得把外部参考体系直接等同于 UOHF，也不得把一般参考知识直接当作个体事实。Human Reference Atlas（HRA）提供人体解剖结构、细胞类型、生物标志物及空间组织的同行评议参考框架[13]；NIH Whole Person Reference Physiome（WPP）正在建立跨器官、跨系统、跨尺度的健康男性和女性人体整合生理图谱与模型[5,6]。在 HFWM 中，HRA 主要提供结构/空间参考知识，WPP 主要提供多尺度生理/机制参考知识。二者都不能自动产生 UOHF 正式关系，也不能自动推出某个具体人的个体因果结论。

本文只公开 Functional Bridge 在 HFWM 中的科学角色与治理边界，不公开私有来源映射表、完整关系库存、检索与重排逻辑、覆盖治理账本、生产提示词、数据库结构、决策权重或其他商业实现细节。
