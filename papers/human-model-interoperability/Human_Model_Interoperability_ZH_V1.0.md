# 摘要

异构人体模型可以指向同一个人，却描述不同的构念、时间点与可能结果。本文提出，将人体功能作为这些模型进行联合解释的共同关系坐标。该架构把任务需求、证据支持的能力、实际功能调用、表现、代价、边界与恢复连接起来，同时保留医学、生理、心理、认知、运动、营养、行为、环境以及设备模型各自的原生输出。人体功能统一本体（UOHF）提供语义身份与受治理关系；人体功能世界模型（HFWM）通过递归子模型、彼此区分的图视图以及版本化更新来协调一个类型化模型网络。本文将通用互操作原则与HFWM的版本约定以及领域特定测量规则区分开来，并把该方案与功能分类、高层本体融合、基于情境的知识融合以及模型组合标准进行比较定位。一个假设性的下楼案例追踪了：独立的能力支持证据与经资格确认的过程观察如何形成特定功能判断；缺失输入如何只限制依赖它的结论；辅助条件或医学预测又如何保持彼此独立。评估议程要求在语义、测量、计算、预测和实际结果层面，将该方案与证据匹配的替代方案进行比较。本文提出的是一个具有明确可检验后果的概念架构，而不是关于普适模型兼容性或临床获益已经得到证明的证据。

# 1. 科学问题：让不同模型能够被联合理解

疾病预测、生理模拟、动作分析以及对日常生活需求的描述，都可能指向同一个人，却回答不同的问题。仅仅因为这些输出出现在同一份记录中，就把它们视为可互换是不成立的。真正需要的是一种方式，把这些答案与以下问题联系起来：这个人必须持续承受或完成什么；当前有哪些身体能力可用；这些能力实际上如何被调用；在采取行动或获得新证据之后又发生了什么变化。因此，这既是数据交换问题，也是计算解释问题。

整合建模并不是新概念。医学数字孪生研究已经处理个体化模拟与整合问题；高层融合长期以来利用本体表示情境与关系；基于情境的知识融合也已明确考虑贡献来源的自主性。真正的问题并不是这些领域是否已经发现了“整合”，而是：当这些模型输出涉及人体功能时，哪些个体层级关系应当被明确表示出来。\[1,2,3\]

我们提出一种架构，以人体功能为组织坐标，把异构模型的贡献组织到同一个持续变化的人身上。其核心关系连接任务需求、证据支持的能力、实际功能调用、表现、代价、边界与恢复。本文拟提供的贡献，是对这些关系及其计算职责进行明确组织，并给出一个可追踪的跨模型案例和可证伪的评估议程。它并不主张仅仅增加一个新标签就能改善推理。

本研究沿着作者已公开的UOHF与HFWM研究计划继续发展，并具体提出一个以人体功能为中心的跨模型互操作架构。论文区分语义承诺、架构设计要求、外部标准以及仍需实证定标的项目。这里的共同协议是一项提议，而不是已经国际通行的标准；文中的案例是假设性设计分析，而不是报告的患者结局。\[4,5,6\]

# 2. 人体功能、UOHF与HFWM属于不同层级

在本框架中，人体功能被定义为“身体为满足内部和外部需求而被适当调用的能力”。能力本身并不等同于实际调用它的过程。何谓“适当调用”，取决于具体的人、需求、情境和相关边界，而不是取决于某一种动作外观、人群平均值或生产率目标。人体功能是一种组织坐标，并不是健康的同义词，也不代表一个人的全部。\[4,5\]

人体功能统一本体（UOHF）提供语义身份、对象区分与受治理关系。人体功能世界模型（HFWM）以这一语义基础为依托，为同一个人的状态、证据、行动、反馈与纵向更新提供组织方式。领域模型则提供各自的机制、估计器、观察、预测或经资格确认的判断。因此，器官模型并不是能力对象，模型输出也不会自动成为关于某个个体的事实。\[6,7\]

表1把通用提议、HFWM实现方式以及使其能够实际运行的领域规则区分开来。对于公开的互操作性主张，这一区分至关重要：共享意义并不要求所有参与者都使用同一家供应商、同一种算法或同一套内部变量名称。

内部调节、防御、恢复、意识、睡眠—觉醒调节、认知与沟通，与运动一样都属于本框架范围。医学是贡献者之一，包括诊断模型与预测模型，但不是组织中心。即使当前无法作出能力解释，心理体验、营养、环境、个人优先事项和医学发现仍可保留其原生意义。一个人选择不参加某项活动，不能被重新分类为身体缺陷。\[7\]

# 3. 与现有方法的关系

世界卫生组织的ICF已经区分标准化环境下的“能力”（capacity）与当前环境中的“表现”（performance），并纳入环境因素。HFWM不应宣称自己发明了“能力”与现实完成表现之间的区分。HFWM的“实际调用”构念关注的是：在一个具体事件中，可用能力通过何种身体过程被组织和使用；它并不自动等同于ICF的performance限定值。二者若要建立对应关系，必须先界定构念与适用范围，而不能仅靠名称替换。\[5,9\]

Little和Rogova提出了用于高层情境理解的关系本体方法；Smirnov及其同事分析了基于情境的融合，并关注来源结构与自主性。这些工作是直接的思想比较对象。HFWM拟提出的贡献，是用于人体模型组合的“需求—能力—调用”解释契约，而不是“保留来源”这一一般思想本身。\[2,3\]

CellML、SBML comp和FMI分别为模型定义、组合与执行提供了互补机制，可以支持HFWM实现中的原生耦合。PROV-O与UCUM可用于来源追踪和单位表示。不能仅仅因为这些标准的设计目标与功能解释契约不同，就把它们描述成较弱的替代方案。\[10,11,12,13,14\]

表2列出了应当进行比较的维度。最后一列提出的是评估问题，而不是已经证明HFWM优越的结果。只要某种替代实现能够保留同样重要的区分，它完全可能取得相同表现。

| **方法**           | **应保留的贡献**                             | **证据匹配比较应回答的问题**                                                      |
|--------------------|----------------------------------------------|-----------------------------------------------------------------------------------|
| 基于ICF的功能表示  | 能力、表现、活动、参与以及环境。             | 与良好实现的ICF信息表示相比，把实际调用作为一个独立取证对象，是否增加了信息价值？ |

| 基于情境的知识融合 | 在考虑来源结构与自主性的前提下进行情境整合。 | 两种系统能否都保留来源依赖，并区分“需求变化”和“能力变化”？                        |

# 4. 一个内核、类型化模型网络与递归组合

HFWM架构采用“1＋N＋递归子模型”的组织方式。“1”是一个版本化协调内核，而不是一个通用数值公式；“N”代表承担不同计算角色的模型。一个模型可以包含子模型，但每次执行都必须展开成有限的必要子图。增加一个模型，不会自动创建一个本体子项，也不要求重新计算所有能力。\[7\]

协调内核负责身份、模型与规则选择，证据资格审查，计算计划，能力与调用判断，安全、权限、版本以及报告投影。多个软件组件可以共同实现这些职责。生理模型、统计估计器、机器学习预测器与规则系统保留各自的数学结构。它们如何进入一次计算，取决于它们承担的角色和被允许产生的输出，而不是取决于模型家族名称。
图1区分四种图视图。组合图表示包含关系；耦合图表示输入、输出、共享变量和时间约束；证据图记录真实的推导关系；任务—能力解释图把需求与经资格确认的证据和判断连接起来。生理学中的反馈回路只要采用适当方式求解就是合法的，但循环推导不能凭空产生独立证据。

人体功能提供组织关系；UOHF提供语义身份与受治理关系；HFWM协调一个绑定于个体的模型网络。原生领域模型可以直接耦合。四种图视图表达的是不同关系，而不是四个串行转换阶段。只有经资格确认的贡献才能支持能力、调用或任务状态判断。医学事实与预测保留各自身份。该图概括了本文以及所引UOHF/HFWM框架中规定的架构。

共享物理状态必须有明确的所有者、只读引用或联合约束。对于同一状态的竞争性估计，应保留各自不同的来源，而不是把它们相加成两个物理状态。重复使用同一观察的模型必须披露这种依赖关系。物理守恒只适用于合适的物理端口，而不能假设存在一个把疼痛、情绪和生理能量全部合并起来的“通用池”。键合图（bond graph）研究说明，在适当的生物模拟连接中，语义一致性与物理一致性可以同时发挥作用。\[7,15\]

四种视图也让分歧变得可解释。组合变化要问的是哪个模块包含哪个模块；耦合变化要问哪些变量或约束发生交互；增加新来源要问哪些断言依赖它；任务变化则要问现在必须满足哪些需求。这些变化可以同时发生，但彼此不能相互替代。同一个测量可以合法支持两个不同问题，而不能因此被视为两次独立观察。一个生理反馈回路可以定义良好，但证据上的循环自证仍然被禁止。

执行范围应由当前问题决定。内核只选择所请求的输出及其必要依赖，而不是评估每个模型或能力目录中的每一项。只有在有明确且经资格确认的降级方案时，才可以省略可选模块。缺失一个必需模块会限制受影响的解释，但不会抹去已有观察，也不能证明存在身体限制。未加载、未测量、不适用、无效以及计算失败，应保持为彼此不同的“无法得出结论”的原因。\[7\]

# 5. 从测量到两个不同的判断

一个能力标准包必须明确：具体构念、适用人群、条件、测量程序、数据含义、估计方法、不确定性、需求比较规则以及适用边界。它回答的是：一项观察能够为某项能力提供什么支持。某个来源结果本身可以有效，但把它迁移到某个具体真实生活任务上可能并无依据。对于某些比较来说，单位一致是必要条件，但单位一致并不能证明构念或测量协议等价。\[7\]

五类参照必须保持彼此分离：适当的人群参照、这个人的任务需求、可比的个人基线、安全与行动边界、以及有意义变化的判定标准。降低任务需求可以改变“是否足够”的判断，却并不增加能力。一次按规定终止点停止的测试，只能证明已经观察到的部分，不一定代表最大能力。在适当规则下，完成20分钟步行可以支持与之匹配的10分钟需求；但仅凭这一事实，不能证明此人无法步行30分钟。

调用标准包则需要绑定具体事件、具有独立证据支持的当前能力、可接受的过程模式、实际过程观察、匹配条件、竞争性解释以及判断规则。所谓“具有独立证据支持的能力”，是指不能循环地用正在被质疑的表现本身去定义并再次确认它自己的能力解释；这并不要求所有观察或模型输入在统计意义上彼此独立。\[5,7\]

表3给出了源版本中的两个判断轴。NORMAL表示：在指定需求与条件下，相关的“足够”或“适当”主张得到了支持。PROBLEM要求存在能够支持相关问题的正向证据。NO_EVIDENCE表示目前缺少作出该判断所必需的证据，并记录原因；它不是“零能力”分数。这些机器标签属于HFWM的版本约定，不是通用诊断。

**表3. 能力判断与调用判断彼此独立。**

| **能力／调用**            | **依据源契约的解释**                           | **不能由此推出的结论**                               |
|---------------------------|------------------------------------------------|------------------------------------------------------|
| NORMAL / NORMAL           | 在指定情境中，两个判断都得到支持。             | 不能据此给出普遍健康、恢复或安全保证。               |
| PROBLEM / NORMAL          | 能力不足以满足需求；对现有能力的调用是适当的。 | 不能自动推断合作失败或调用异常。                     |
| NORMAL / PROBLEM          | 能力得到支持；实际调用存在独立证据支持的问题。 | 不能据此确立神经、结构或心理原因。                   |
| PROBLEM / PROBLEM         | 两个问题各自都有充分证据。                     | 任一轴都不能自动证明另一轴。                         |
| 已知能力 / NO_EVIDENCE    | 保留已支持的能力判断，并把调用维持为未解决。   | 不强行生成完整画像。                                 |
| NO_EVIDENCE / NO_EVIDENCE | 保留观察、约束和精确的证据缺口。               | 未知不等于正常、不等于受损，也不等于“没有记录事实”。 |

当当前能力缺少足够的独立支持证据时，本源版本不允许给出已知的正式调用判断。整合任务状态类别仍属于另一层解释。

正常、代偿、临界和失能，是另外定义的任务状态类别。它们需要相应状态规则，并考虑后果、边界与恢复；它们并不是能力或调用的量表。安全阻断、证据缺失和数值求解器失败也必须保持为不同状态。辅助或替代策略可以是适当的，而提示后表现改善本身并不能说明改善为何发生。\[7\]

对于多维能力，已经观察到的成功点并不能确定所有可达到的组合。各维度的单独最大值也未必能够同时实现。父级能力的解释同样需要有独立依据的综合规则，而不能默认取子项的最小值、最大值或平均值。如果缺少这种规则，系统应报告已知的子项结果以及尚未评估的维度。对于没有下位条目的能力也应遵循同一纪律：当前目录直接保留C07“持续任务耐力能力”，而不是为了让层级看起来对称而虚构子项。\[7,8\]

需求条件化判断应当保持实用，但不能变成贴在个体身上的永久标签。对于一个有辅助、负荷更低的任务，能力可能足够；而对于另一项需求又可能不足。这种差异可能来自任务需求，而不一定代表身体能力发生了变化。因此，报告应保留能力—任务关系以及证据截止时间。只有当数值储备、有意义变化或恢复时间各自的量表、测量解释和条件获得支持时，才报告这些量；仅仅完成一个任务并不能提供这些信息。

# 6. 医学及其他领域的贡献

一个通用模块接口包络应标识模型与运行实例、个体、预期用途、适用人群、输入、输出类型、单位、时间、状态所有权、依赖关系、不确定性、失败行为与替换条件。它保留生产者的原始输出，同时单独限定该输出与接收方构念之间的关系。因此，一个合适的接口可以接收有信息价值的医学预测，而无需人为制造一个能力估计。\[7\]

医学模型包括诊断、疾病风险预测、预后、早期预警、并发症以及治疗反应预测。每一个预测都应保留其终点、时间范围、版本、输入与适用性。FHIR RiskAssessment展示了一个现有的预测结果及其依据的表示方式。接收这样的记录本身，并不能验证HFWM映射，也不能把“风险”转换为当前功能受损。\[16\]

当医学预测的预期用途支持时，它可以触发允许的重新评估问题或行动复核。反过来，经资格确认的人体功能观察也可以成为某个医学预测器的输入，前提是其输入契约允许。返回的预测是从这些观察推导出来的，不能再被作为独立测量来确认这些观察。改变预测器的输入集合需要重新评估；不能默认加入更多功能特征就会提高准确率。

同一契约也适用于训练反应、睡眠、行为或环境暴露的预测。原生生理和生物力学模型可以直接交换兼容变量。认知、心理与营养模型只能在其构念和经过验证的用途范围内作出贡献。设备信号、派生指标与专业解释仍是不同对象。通用人工智能可以组织信息或表达有证据支持的陈述，但任何学习型估计器仍需要明确其角色并独立完成验证。

在内部过程和非医学领域，这种区分尤其重要。关于营养摄入的记录本身，并不是对营养加工或可利用性的估计。内部调节模型可以提供与该问题有关的变量或约束，但只有经资格确认的构念模型，才能把适当证据转化为能力估计。同样，对心理体验的记录保留的是个体所报告的内容；情绪调节或认知解释需要各自独立的构念、情境与证据。这些例子说明的是可能承担的角色，而不是已经完成的整合。\[7\]

无论当前是否存在外部任务记录，身体变化和有用观察都可以存在。内部调节、保护、修复和发育仍属于本框架的需求范围。把内部任务纳入实际运行，需要受治理的定义与触发依据；一个疾病关键词并不会自动实例化所有内部任务。当没有足够观察或比较依据时，相关过程或医学事实仍可以被表示，而无需附加一个没有证据支持的能力标签。这样既避免把人体功能缩减为可见运动，也避免把每一个生理测量都当成“测得的能力”。

# 7. 一个完整的假设性连接：下楼梯

下面的设计案例扩展了源设计稿中的下楼梯示例。它不是参与者记录。案例中凡被表述为“证据充分”的测量有效性、任务迁移规则和过程比较规则，都只是为说明而明确设定的假设；本文并未给出临床阈值、诊断或设备性能。目的在于准确展示：哪些贡献使某个判断成为可能，哪些贡献并不能做到这一点。\[7\]

该个体的目标，是在明确的台阶几何、速度、携带负荷和辅助条件下，下完一段熟悉楼梯。焦点能力是制动输出能力；它只是整个任务涉及的多个能力之一。即便对这一能力作出判断，也不能证明整个下楼任务已经合格。表4列出了来源记录及其不同角色。

**表4. 案例输入、保留的身份与允许用途。**

| **示例记录** | **来源贡献与条件**                                                                     | **允许承担的角色**                                               |
|--------------|----------------------------------------------------------------------------------------|------------------------------------------------------------------|
| 任务 T1      | 受治理的任务描述记录台阶几何、速度、负荷、阶段、辅助方式以及成功完成条件。             | 定义焦点制动需求；不能证明个人能力不足。                         |
| 评估 A1      | 独立获得的评估，在明确适用的解释与任务对齐规则下支持制动能力。                         | 在本示例中，假定它支持焦点T1需求是足够的。                       |
| 过程 O1      | 独立的任务过程观察记录T1下楼过程中的制动组织方式；假定条件匹配并存在经批准的解释规则。 | 在本示例中，假定它支持“尽管焦点能力足够，但实际调用仍存在问题”。 |

| 报告 R1      | 报告引用A1、O1与P1，而不是增加新的测量。                                               | 面向受众的投影，具有相同来源谱系；不产生新的独立证据。           |
| 随访 O2      | 后续下楼使用了额外支撑，并观察到表现改善。                                             | 这是一个新的有辅助条件事件，不能证明能力已经改善。               |

这些标识符仅用于本假设性示例，不是生产记录，也不是新的本体标识符。在实证研究中，这些“证据充分”的假设必须被真实协议与真实来源所替代。

首先，任务解释确定相关阶段具体需要什么。其次，对评估结果的解释与任务对齐，确定焦点制动需求是否得到满足。第三，独立的过程观察和规则，在匹配条件下支持一个调用问题。三者共同形成该能力—任务关系下、受需求约束的NORMAL / PROBLEM判断。没有任何单一诊断、任务标签或视频发现能够独自给出这一完整结论。其他未评估能力仍保持未知。

此时，报告可以写成：“当前证据支持在这些条件下所需的制动能力，但在下楼过程中对该能力的实际调用仍存在问题。具体机制尚未解决；后续工作应在适用安全边界内，针对实际过程与竞争性解释继续评估。”这是一个积极的功能解释，而不仅仅是拒绝推断。它既不直接开出治疗，也不通过某一医学诊断来解释该发现。

如果删除A1，或者删除其有效的任务对齐规则，那么“能力足够”的结论就不再成立。O1、不适体验以及辅助条件仍应保留，但在该契约下，能力判断和调用判断都保持未解决。如果保留A1，只删除对O1的经资格确认解释，那么能力判断仍为NORMAL，而调用为NO_EVIDENCE。某项观察缺失，不会抹去彼此无关且已经得到支持的信息。

当O2显示在增加辅助后表现改善时，系统记录的是一个新的情境。得到支持的变化首先是“有辅助条件下的表现改善”；它并不能追溯性地证明第一次困难由某一种特定原因造成，也不能证明身体能力已经增加。医学预测仍保留在它自己的未来时间范围内。一个新的、适用的医学限制可以修改允许的行动集合，而无需把焦点能力判断改成PROBLEM。同一个人在这些不同对象和更新之间始终得到保持。

# 8. 时间、权限与“变化”的含义
HFWM把身体真实变化、测量、知识修订和模型演化区分开来。观察时间、回顾窗口、数据进入系统的时间以及推断或确认时间具有不同含义。迟到的评估证据可以支持我们修订对过去某一时期的解释，但不能把生物事件的发生时间移动到上传日期。此前已经确认的报告应继续保留，并链接到后续更正，而不是被静默覆盖。\[7\]

同一个已存储信号，在算法发生变化后重新处理，可能导致估计结果改变，却并不能证明身体发生了变化。依赖声明用于识别哪些当前判断需要重新资格审查。兼容的模块替换应保留下游使用者所依赖的意义与保证，但输出变化仍需复核。如果意义、不确定性、输入假设或时间定义改变，则必须重新考虑契约版本以及受影响的模型组合。

行动是否“有资格被执行”，与“哪一个行动看起来最有吸引力”是两回事。必要的安全、同意、权限、预期用途证据和实际可行性条件必须全部满足。对某一结局的预测，不会自动成为改变行动有效性的证据。计划并不等于已经实施的干预。共同语义也不意味着可以无限制共享个人数据：共享模型治理可以与区域化数据处理和目的限定的数据交换并存。\[7\]

模型升级又是另一类变化。替换模型可能在提升精度的同时保持输出含义不变，也可能改变输入条件、不确定性或输出构念。前一种情况仍要求复核受影响的下游判断；后一种情况则需要明确的契约迁移或语义迁移，而不能静默替换。历史报告继续显示当时使用的来源版本和模型版本。因此，保持接口兼容并不意味着冻结未来科学，也不承诺所有可能输入都会得到完全相同的数值。\[7\]

治理还决定什么可以被共享。共同模型定义与交换规则，并不意味着要建立一个无限制汇集个人数据的全球数据库。每一次交换都应有明确的个体、目的、接收方与最小必要内容。即使两个人使用同一个模型定义，其个体层状态也必须彼此隔离。这些是架构要求；法律合规、安全和区域部署需要单独审查，不能由概念模型本身证明。

# 9. 什么才算支持该方案的证据？

核心假设是：在给定相同证据的前提下，明确表示“需求—能力—调用”关系，能够比强有力的替代方案产生更有效、更有用的跨模型解释。比较不能把“更多数据”“更多专家投入”或“更复杂的文字表达”误认为架构优势。应允许具有同等表达能力的替代方案获得成功；这里要检验的是可测试的行为，而不是某种表示方式的排他所有权。

评估应分别考察语义一致性、测量与构念效度、组合计算、判断与预测，以及服务结果或用户理解。V3与COSMIN提供了与测量验证有关的重要区分，但二者都不能证明整个模型网络有效。对于每一种预期用途，都必须独立规定所需证据。\[17,18\]

案例标签应依据独立评估证据与明确条件进行裁决，而不能用“是否与HFWM输出一致”来定义真值。既要测试有充分依据的正向判断，也要测试合理的未知状态。值得考察的错误包括：无依据地把结论迁移到另一个任务、把辅助改善误认为能力改善、把返回的预测重复计数为独立证据，以及把算法失败误认为个体失能。在提出任何临床获益主张之前，就可以先测量测量错误与判断错误。

预测研究需要在个体和时间层面进行适当隔离，并明确终点、校准与分布漂移检查。干预研究需要针对行动本身的效果提供证据，而不能只看预测准确率。模型替换研究既要考察单个模块性能，也要考察受影响的下游解释。用户评估则应询问：人们能否解释当前已知什么、仍不确定什么，以及为什么提出下一步。这些都是计划中的研究要求，并不是本文已经报告的结果。

三个对比可以进一步明确研究问题。第一，把“只是把一次测试和一个任务放在一起”的记录，与“明确判断该测试是否足以支持该任务需求”的记录进行比较。第二，把一般性的表现解释，与“要求能力证据和实际过程证据彼此分开”的解释进行比较。第三，在模型或条件变化后，把无差别地重新计算一切，与基于依赖关系进行重新资格审查进行比较。一个设计良好的替代系统也可能实现这三点；如果如此，研究就应比较二者在成本和可复现性上的等价性或差异，而不是重新定义成功标准来偏向HFWM这个名称。

最有力的证据应同时包含“有依据的结论”和“有依据的克制”。一个总是返回未知的系统可以避免一部分错误结论，却可能无法服务于人；一个把所有字段都填满的系统则可能掩盖没有依据的推断。因此，评估应同时统计：漏掉的有支持结论、无支持结论、被正确保留的有效部分结果，以及被准确解释的证据空缺。专家分歧和不确定的参照判断也应保持可见。源设计中的验收场景可以作为设计目标，但真正的实证研究必须提供实际输入、版本、结果和独立裁决。\[7\]

# 10. 局限与结论

本文规定了一个架构，并对假设性案例进行解释。它没有为每一项能力提供完成定标的规则，没有证明任意外部模型都能被整合，也没有证明比较优势。18/104能力目录、源设计要求以及个体数据是否充分，是彼此不同的成熟度主张。共同的人体功能坐标也不能替代个人价值、医疗可及性、社会机会或专业判断。

该架构把领域方程、参数、测量工具和比较标准留给具备资格的具体实现。一个共同接口可以让假设变得可检查，但不能让假设因此变成真的。因此，其科学价值既取决于各组件本身是否有效，也取决于这些组件组合使用时是否有效；无论是一个目录，还是一致的数据结构，都不能单独证明这一结果。

完整人建模并不需要取代专门的人体模型。它可以保留各领域模型自身的意义，同时明确显示：经资格确认的贡献如何支持同一个人的需求、能力、实际调用与变化。UOHF提供语义基础；HFWM规定协调、证据与更新职责；领域模型提供各自的科学内容。对这一拟议公共协议的评价，应取决于这些关系能否产生有效、有用且可复现的解释，而不是取决于其名称覆盖范围有多大。
